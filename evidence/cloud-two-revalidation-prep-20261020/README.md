# 剩余两个云端接管中断点

本批依据用户“这三个优先跑”及所选第二、三、四项任务执行，其中故障范围仅为之前未进入接管阶段的 `E1-a/after_observation` 与 `E1-a/before_modification`，各一次，模型调用 0。

执行器沿用四例批次的实现，作为独立文件保留旧批次脚本与记录；只收窄计划、校验和授权至两个中断点，使用新的计划、事故、授权和结果目录。当前源码与实际云镜像重新绑定；不把旧失败改判为成功。

使用既有 NEW7 云业务、统一身份租约与空闲交接。包含数据库只读、连接池故障与恢复、实验主智能体退出、原 journal 离线 access 恢复、正常关闭本批自有 SDK 群组和六域消费者；每例独立检查 30 秒、10 个完整订单流程。清理不确定则保留隔离，清理核实后归还身份并确认巡检实际恢复。

本批短暂停顿纳入连续运行报告。复验完成后记录新的连续窗口起点，不能将计划中断拼成无中断 24 小时。无需重建或拉取镜像。

本目录的 `test_cloud_batch.py` 验证两例范围、授权哈希、统一租约相关配置和正常信号清理；离线通过不等于真实复验通过。实际结果另外保存。
