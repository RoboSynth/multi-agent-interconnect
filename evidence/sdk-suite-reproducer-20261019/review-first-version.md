# Portable SDK runner review

Reviewed `run_sdk_suite.py` and `synthetic_tls.py` as read-only source, plus the existing `run-first` evidence and the relevant SDK test/configuration files. No tests, platform, model, or network were started during this review. Implementation files were not edited.

## Confirmed findings

1. **P2 — A virtual environment inside `--repo-root` loses its dependencies.** At `run_sdk_suite.py:154-155`, the worker removes every existing `sys.path` entry below the entire repository. A normal `<repo>/.venv/Lib/site-packages` or `<repo>/.venv/lib/pythonX.Y/site-packages` therefore disappears, even when selected explicitly with `--python`. `helper.make_tls()` then imports `cryptography` at line 161, followed by the test dependencies at lines 168-173, so dependencies installed only in that valid virtual environment cannot be imported. The selected executable's POSIX symlink is correctly preserved at lines 62-64, but this later filtering defeats that protection for repository-local environments. The existing successful run used `--repo-root .../checkout` and a runtime environment outside that checkout; it does not exercise this case. Preserve the selected environment's dependency directories while excluding repository source paths, or explicitly constrain/document the environment to live outside `--repo-root`.

2. **P2 — Inherited `TMPDIR` can move temporary test writes outside the requested output.** At `run_sdk_suite.py:146-150`, the worker overrides `TEMP` and `TMP` but leaves `TMPDIR` inherited. Python `tempfile` gives a usable `TMPDIR` priority over both, including on POSIX. The current checkout calls `tempfile.TemporaryDirectory()` without an explicit directory in `tests/resumable/test_resumable.py:29,166,274`, `tests/aip/test_task_ordering.py:42`, and `tests/amp/test_message_emitter_concurrency.py`. On a host with `TMPDIR` set, those test writes use that external path, so the output boundary and independence from ambient host configuration are incomplete. Set `TMPDIR` to the new output's temporary directory as well. This is a static finding; no Linux run was performed.

## Supported behavior and limits

- The public driver requires a new output directory (`mkdir(..., exist_ok=False)`), rejects output under the SDK source tree, copies the inventoried source, and verifies each copied file's hash. Normal public invocation cannot overwrite an existing output. JSON and generated TLS files use exclusive creation. This is an output-management boundary, not an operating-system sandbox for arbitrary test code.
- The complete current checkout's SDK `tests` directory is passed to pytest, without `-k`, `-m`, node selection, or ignore arguments. The checked `pyproject.toml` has only `asyncio_mode = "auto"`; no filtering configuration was found in the relevant current test tree. `PYTEST_ADDOPTS` and `PYTEST_PLUGINS` are cleared, plugin autoload is disabled, and the needed asyncio/anyio plugins are explicit.
- Source SHA-256 inventory, copied SDK source, original SDK source, fixture hashes, and loaded SDK module paths are bound to the run. Cache directories and `.pyc`/`.pyo` are deliberately excluded; this is a content inventory, not a filesystem-metadata or arbitrary source-mutation sandbox.
- `run-first/driver-result.json` records worker/driver/pytest exit code 0 and 605 passed calls. `run-first/results.json` records exact source snapshot, original SDK source, fixture integrity, and SDK imports from the snapshot. The current runner SHA-256 equals the run's `f3ac492639a8bf24b3ffcf78ab1dba4f692fb44850fb482459c164a941f0e922`. These are existing Windows Python 3.12 execution results, not a Linux execution claim.
- Normal pytest failures remain nonzero; integrity failure forces a nonzero exit. Successful result writing preserves the raw pytest exit code separately. Worker exceptions write `worker-failure.json` when possible and propagate nonzero status; driver stdout/stderr files retain worker output. The review did not execute a deliberate failure case.
- The TLS helper generates fresh RSA keys and synthetic certificates locally. It reads no registered credentials, persists no CA private key, and returns only certificate/public-key identifiers in its public report. Leaf private keys remain in `suite-copy`; publish only the intended public metadata, not the entire output tree.
- The two runner files must remain together. Python must satisfy the SDK's `>=3.10` requirement and already provide the needed dependencies. The optional existing `evidence/sdk-test-integration-20261019/source-manifest.json` is read if present; it is not required, but a malformed present file currently aborts preparation. No hard-coded machine-specific interpreter or dependency path appears in these two runner files.

Disposition: the existing 605-pass Windows result is supported. Unqualified portability to a normal repository-local virtual environment, or confinement of all temporary writes to `--output` on a host with `TMPDIR`, is not supported until the two findings above are addressed.
