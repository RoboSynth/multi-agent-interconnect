# P1 / P3 / P4 本地修复（2026-10-19）

## P1
八处 SDK message 打点共用 taskId 关联函数，管理消息保留 sessionId；Start 发送给多个或零个参与者会告警。真实收发边界与单接收方 access 配对离线测试通过，未向平台发送日志。

## P3
ACL 幂等 PUT/DELETE 与只读 ADP 查询最多尝试四次，显式分段超时与关闭环境代理，DELETE 404 作为已删除处理；创建群组和邀请本身不新增盲重试。ACL/通知失败仍尝试自有 MQ、通道和连接清理，聚合错误保留 unknown 状态及所有权，失败后的断开会话可再次幂等清理而不重复通知。新增项与既有相关回归共 134 个不同测试通过（另有 52 subtests），原导入失败与沙箱阻塞记录保留在 sdk-checks.json，平台批次尚未复验。

## P4
平台和本地接管统一保留 initial_error_class、takeover_error_class、takeover_reason、takeover_rejection，继续抛原任务异常并保留异常链，拒绝及 operation=null 不会覆盖真实原因。共享历史字段生产端至 Bridge 契约和既有接管回归通过，未修改冻结批次或改写既有实验结论。

## P2 交接所依赖的参与者清理
消费取消或自有队列删除失败现在保留资源引用和结构化未知状态，并继续关闭其他自有通道与连接，最终传播错误至托管进程退出路径。外借连接和 Leader 交换机不会被关闭或删除，新增两个失败 mock 与既有成功路径共 23 项通过。
