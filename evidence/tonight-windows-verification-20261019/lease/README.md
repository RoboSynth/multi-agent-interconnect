## 复核结论

- 每例都需要严格业务恢复、30 秒/10 个完整订单流程的 H00，以及完整关闭检查，才能继续；单次失败仅在有明确所有权和 ACL/队列/交换机/消费者清理回执时才继续。
- 失败或取消没有完整清理回执时，批次保存失败和未执行条目，租约写持久隔离文件，释放本地文件锁，并给巡检发送 `quarantine`，不发送 `resume`。补测验证了取消异常继续向调用者传播。
- 正常交接先等待巡检确认消费者关闭并释放七身份，再取得同一目录下的全部身份锁；全部案例确认清理后先释放锁，再请求巡检恢复。测试中同时申请相同身份会被拒绝。
- 默认租约目录与旧 `coordinator_lock` 的路径和锁字节约定一致。它只排斥同机、同目录的参与者，不能判断队友电脑是否仍在使用身份。
- `run_leased_batch` 是无 CLI 的编排辅助函数，不校验冻结源码与授权；具体新执行入口仍须绑定计划、源码、七身份和资源所有权。不可把旧 `coordinator_lock` 嵌套在已取得七身份的回调中。

没有发现需要修改 `eval/leased_batch.py` 的具体缺陷；本次只新增取消行为测试。上线、真实平台交接和跨电脑身份排他性不在本次离线结论范围内。
