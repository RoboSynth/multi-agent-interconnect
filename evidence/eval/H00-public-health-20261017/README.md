# H00公共HTTP观察器实跑：失败与修复

两次运行均使用原生订单入口的公开HTTP接口、唯一测试请求命名空间及1rps业务流。没有故障注入、资源设置修改、模型调用或平台群组调用，也没有读取资源凭据。它们验证的是`ContinuousObserver`的真实业务窗口，不是完整`eval.run`或正式平台健康对照验收。

第一次在完成30请求后，调用方停止与采集协程下一请求竞跑：实际31次请求均成功、10完整流程，但剩余一个未完成流程，`healthy_control_confirmed=false`，控制脚本exit1。原失败和该版本源码快照保留。

修复后由采集协程在完整chunk边界判定结束，调用方仅登记停止请求和截止时间。独立新目录复验实际30次请求、30次成功、10完整流程，窗口30.235秒、控制观察30.25秒，未完成/失败/未知均0，`healthy_control_confirmed=true`、`recovery_confirmed=false`，脚本exit0。

配套离线检查确认：H00任何act尝试均失败，包括拒绝、未知或未派发；健康对照单列，不计入故障恢复率分母。缺少动作尝试证据的历史H00行保持未验证。完整评测结果仍须结合运行器的任务日志和零act尝试条件。

团队目录中的`first-failure.json`与`safe-stop-v2.json`是两份精简原结果的逐字节副本，排除了逐请求状态和原始业务键；源代码SHA各自随结果记录。历史故障与模型数据不重生成或改名。
