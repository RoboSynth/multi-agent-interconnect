# 访问日志持久化与进程恢复（2026-10-19）

当前 `AmpRuntime` 已接入 `DurableAccessEmitter`。处理 Start 前先持久化请求的身份、路由、关联键和稳定日志 ID；回调结束后先固化完整日志，再追加 JSONL 并同步到磁盘。写入失败保留待写记录，5秒周期、正常关闭或下次启动继续写出同一条内容。

硬退出可能发生在资源修改之后、结果落盘之前。这种情况下，新进程取得日志独占所有权后写出 `OutcomeUnconfirmed`，省略 `response` 和 `durationMs`，时间戳表示恢复时的观察时间。原进入时间仍保留在本地 journal。它不表示业务修改失败，也不会触发业务重做或改变 AIP 任务状态。

## 接入与恢复

项目各域继续通过 `AmpRuntime` 向原 GroupLeader/Partner 注入 `amp.access`，调用方式不变。SDK 单独使用时可选择 `DurableAccessEmitter`；原 `AccessEmitter` 的默认行为和 API 保留。

同一资源域重启时，使用原 AIC、原日志绝对路径和同目录的 `.outbox.sqlite3`，在接收新任务前调用 `start_sync()`；`AmpRuntime.start()`已执行这一过程。仅恢复日志也可以创建发射器、调用 `start_sync()`，最后 `close_sync()`，无需发平台任务或重新执行资源操作。每个日志文件有独立 journal；实验专用目录必须由所属域以原路径显式恢复，不会自动扫描其他目录。

一个规范化日志路径只派生一个 journal，持久保存 AIC/路径绑定。SQLite 独占连接防止两个进程同时接管，线程调用串行；活动回调未结束时关闭会报错，保持所有权。稳定 ID 对应的正文一旦固化就不再更新。若日志里已存在相同 ID 和内容，先同步已有文件，再确认待写记录；同 ID 不同内容、半行、坏 JSON、文件替换或截断均停止重放，保留原字节。

保留日志和 journal 的原位置；迁移或更换身份时另选新的日志目录并保留旧材料。不要把旧 journal 复制到另一个日志路径后继续使用，也不要并用普通发射器写同一个 JSONL。Fluent Bit 仍只采集 `amp_*.jsonl`，SQLite 不进入转发通道。

## 原有实验与后续验收

原22例保持18通过/4失败、缺18条access；修复复验12例保持11通过/1失败、缺12条access。它们的原镜像、原日志和原判均未改写。本轮没有部署新镜像、启动平台身份或执行新故障。

下一次正式复验须绑定本轮源码、新镜像和日志恢复步骤。特别是实验 worker 的独立 AMP 目录，必须在所属域恢复同一 journal 后再采集闭合结果；不能借正常 worker 的另一目录补端。Kafka/Monitor 参数与权限、新机器部署、长期窗口和最终交付材料继续独立处理。

规范依据为官方 AMP 的稳定 `logId`、至少一次投递和不可变重投，以及可省略结果字段的 AccessBody；本项目不使用同 ID 修改正文的 upsert。具体源码、规范位置和 SQLite 独占锁依据见[语义审阅](../evidence/access-durability-20261019/review/semantic-review.md)。
