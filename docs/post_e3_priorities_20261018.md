# E3之后的三项优先工作

这是协作安排，不是完成报告。E3的实际退出、恢复表现与收尾以后续独立证据为准；旧初审表和历史专题的“尚未运行”文字不能代替当前事实，也不能直接推断缺代码。

[开发者接手](开发者接手指南_20261018.md) · [协作任务清单](协作任务清单_20261018.md) · [巡检启动方案](new7_inspect_preparation_20261018.md) · [正式E1适配方案](new7_e1_adaptation_20261018.md)

## 1. 开始真实长期巡检，补AMP平台入库（T04—T07、T63）

24小时和7天需要真实时间积累。既有NEW7健康任务、登录单实例脚本和固定窗口统计可复用；短时实验、注册任务或本地jsonl都不能证明长期在线或平台入库。

- **可接手：** 按[巡检启动边界](new7_inspect_preparation_20261018.md)，在E3正常关闭和同AIC释放后准备唯一巡检，关闭主动drill、模型、自动接管及high自动审批。inspect仍可能执行write级修复，须如实记录act。固定UTC窗口、期望七AIC、心跳周期、每次30秒/10完整流程及中断；用[固定窗口语义](stability_report.md)保留缺席身份分母，分别报告采样完整度和真实可用性。
- **外部依赖：** 持续开机/登录窗口，以及赛方Kafka地址、TLS/认证、Monitor/Discovery查询权限；不要求额外Linux云主机。未获得的配置列待确认，不把本地日志写成已入库。
- **完成证据：** 一个完整24小时无人工修复窗口，随后累积7天；可关联的本地AMP与平台可见记录、访问量增长、Monitor验签/去重及真实中断。真实登录、重启另留证。

参考：[登录巡检](windows_startup.md)、[平台待确认项](赛方确认.md)、[NEW7健康边界](new7_platform_20261018.md)。

## 2. 正式NEW7主备接续与脑裂拒绝（T32、T61）

本地18例、旧主复活和NEW7健康结果分别保留。本轮E3协议关闭自动接管，不能覆盖正式ADP重发现、资源匹配、备库入群和剩余任务接续。

- **可接手：** 按[具体E1源码缺口与实施顺序](new7_e1_adaptation_20261018.md)，先开发独立薄runner和默认无动作入口，复用现有接管、journal、共享账本及fence。首个闭环选after_applied，绑定发现→describe→邀请→ResumePackage→原operation_id对账；闭合后再扩大断点、交接表示与同进程复活计划。
- **外部依赖：** 已有NEW7身份和本机容器可复用，同AIC独占排期；F15、参与者退出、pause/unpause与旧主重放须单列实际资源、次数、恢复边界并获得对应授权，不能沿用E3的45格范围。
- **完成证据：** 正式AMQPS任务/产物/账本与实际MCP调用对账；副作用只发生一次、重复效果0、旧epoch修改实际被拒绝。按方法列接管耗时和usage，确定性续办的0模型调用不能包装成LLM token收益。每次独立复原后公共v2至少30秒/10完整流程，failed/unknown/pending/unresolved为0，正常关闭自有群组。

参考：[原高分方案](高分方案_需求架构创新与任务_20261017.md)、[P0审计](P0完成审计_20261017.md)。

## 3. 由另一位开发者完成干净环境部署与F10（T11、T96）

同机快照冷部署、Compose解析、归档和配置边界检查只能覆盖局部问题。需要独立开发者按最终仓库从依赖准备到完整故障流程记录真实反馈。

- **可接手：** 固定团队提交，按[接手指南](开发者接手指南_20261018.md)和[部署入口](../deploy/README.md)列计时点，明确Python/PowerShell/Docker/模型、私密配置生成、端口及可选身份步骤。记录命令、实际退出、下载/缓存、错误与耗时，只据具体复现修部署缺陷。
- **外部依赖：** 独立干净Windows/WSL或Linux环境与下载网络，不要求租云主机。各人持自己的私密材料；正式联调用独立身份或独占窗口，不复制正在运行的NEW7私钥。F10只针对该次明确允许的独立资源。
- **完成证据：** 固定提交/源清单、完整首次部署日志、资源/身份归属、F10注入与恢复、公共v2的30秒/10流程和实际退出。按方案核15分钟目标，下载与缓存条件、超时和首次失败如实保留；已配置开发机重启不能替代本项。

参考：[开发归档边界](development_archive.md)、[本地验收](本地开发验收.md)。

三项可分别分工，但共享NEW7身份的实际操作顺序排期。每个工作包先确认文件所有权和验收证据；持续巡检、E1与评测不得并行消费同一AIC。PPTX继续按用户安排暂缓。
