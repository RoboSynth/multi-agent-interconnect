# 公开故障复盘：跨域排障的三个真实案例

三家服务商的一手复盘共同呈现了跨域状态不一致、处置冲突和观测通道失效三类排障困难。下文记录原文事实；“作品对应需求”是本项目据此提炼的设计需求，不表示作品已在这些生产环境得到验证。

资料查阅日期：2026-10-19。涉及方按原文披露列出，未披露的内部团队总数不自行补齐；时长区分业务受影响、基础设施恢复和事故关闭。

## 1. GitHub：43 秒网络分区引发 24 小时 11 分钟服务降级

**时间与涉及方。** 2018-10-21 至 10-22，GitHub 平台及用户受到影响；原文明确提到首响应团队、数据库工程团队和事故协调者，未公布全部参与团队或供应商数。网络维护期间的 43 秒断连触发跨区域 MySQL 主库切换，两个区域出现尚未互相复制的写入，无法直接安全切回。官方给出的服务降级时长为 **24 小时 11 分钟**。[官方复盘](https://github.blog/news-insights/company-news/oct21-post-incident-analysis/)

| 原文关键时间（UTC） | 事件 |
| --- | --- |
| 10-21 22:52 | 网络分区并触发数据库切换 |
| 10-21 23:13 | 数据库工程团队介入恢复拓扑；一致性约束影响回切选择 |
| 10-22 11:12 | 主库重新位于东部，副本仍存在延迟 |
| 10-22 23:03 | 积压处理完成、系统运行确认后恢复绿色状态 |

**卡点及作品对应需求。** 数据库自动切换的拓扑与应用延迟假设不一致，恢复还必须兼顾数据一致性和后台积压。本作品需要跨资源域共享结构化证据、检查修改前置条件，并用业务流程确认恢复，不能只以某个进程或主库恢复判定事故结束。

证据定位：原文“Background”“Incident timeline”“Technical initiatives”；23:13、11:12、23:03 三个时间节点。

## 2. Cloudflare：多人回滚互相覆盖，19 个数据中心受影响

**时间与涉及方。** 2022-06-21，涉及 Cloudflare 网络工程人员、19 个受影响数据中心及依赖其服务的客户；内部团队总数未披露。路由策略条目重排撤销了关键前缀，并使工程人员难以进入受影响站点回滚。[官方复盘](https://blog.cloudflare.com/cloudflare-outage-on-june-21-2022/)

| 原文关键时间（UTC） | 事件 |
| --- | --- |
| 06:27 | 变更到达新架构站点，故障开始 |
| 06:58 | 明确根因并开始回滚，首个数据中心恢复 |
| 07:42 | 最后一个站点回滚完成，所有数据中心恢复 |
| 08:00 | 事故关闭 |

按原文时间线计算，故障开始至全部数据中心恢复为 **75 分钟**，至事故关闭为 **93 分钟**。原文明示回滚期间工程人员互相覆盖变更，甚至撤销了先前的回滚，使故障间歇重现。

**卡点及作品对应需求。** 连接恢复通道受损与并发操作冲突叠加，延长了处置。本作品需要操作所有权与隔离令牌、修改状态账本、接管前核实既有操作；需要验证的是减少冲突和重复操作的能力。

证据定位：原文 06:27–08:00 时间线及其回滚冲突说明段。

## 3. AWS：内网拥塞连带损害监控与部署，拖慢恢复

**时间与涉及方。** 2021-12-07，AWS US-EAST-1 的内部网络、DNS、运维及依赖控制面能力的服务和客户受到影响；原文未公布参与团队总数。自动扩容触发连接激增，重试进一步加重网络设备拥塞。[官方复盘](https://aws.amazon.com/message/12721/)

| 原文关键时间（PST，UTC−08:00） | 事件 |
| --- | --- |
| 07:30 | 自动扩容触发异常连接活动 |
| 09:28 | DNS 流量迁移完成、解析错误恢复，整体拥塞仍在 |
| 13:34 | 拥塞显著改善 |
| 14:22 | 网络设备全部恢复；后续各服务仍有各自恢复进度 |

按时间线计算，开始至网络设备恢复为 **6 小时 52 分钟**，不是所有服务统一恢复时长。原文指出监控数据不可用、内部部署系统受损、以及必须避免影响仍健康的工作负载，共同放慢处置；API Gateway 的自动替换还依赖 EC2 API 恢复。

**卡点及作品对应需求。** 诊断与恢复工具依赖同一受损基础设施，单个域恢复不等于业务全链路恢复。本作品需要保留本域证据、显式处理依赖与未知状态，并对健康资源限制修改范围。

证据定位：原文“Issue Summary”的拥塞、监控与部署段，以及“AWS Service Impact”的 API Gateway/EC2 依赖段。官方复盘发布于 2021-12-10。

## 可用于需求分析的结论与局限

三个案例支持三项需求：跨域证据要能对齐，修改需要所有权与可追踪状态，恢复需要业务验证。它们为需求提供公开依据；用户是否普遍遇到这些问题、是否接受本作品的权限模式，仍由[实际访谈与问卷](访谈与问卷.md)回答，不能用公开复盘代替本队用户访谈。
