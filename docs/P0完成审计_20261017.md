## 需要优先补齐的不变量

1. **两项第三方 MCP。** 第一项真实 Postgres 已证明。第二项必须是上游 `ckreiling/mcp-server-docker` 经官方 MCP client 对真实带标签容器执行，不可拿自研 Windows 进程 MCP 顶替。优先独立端口与数据卷，避免干扰现有原生演练。
2. **接续效果分层。** 已证明数据库唯一键/同事务回执、共享操作账本和旧 fence 检查；它们分别属于业务与协同层。尚未证明正式 ADP 接管、三交接方法优势或旧主复活脑裂。报告必须分开统计效果次数和 MCP 调用次数，保留结果未知/需观察的中间状态。
3. **公平调度实验。** 固定模型、精确模型文件、温度/采样参数、工具集合、每方法预算、场景实例、随机种子与重复；M1 的自由循环须与定义相符。规则回退应标记 fallback；不能把规则跑出的探测减少称为 LLM 效果。当前 30 秒验证流量只在修复后启动，不能替代所有方法相同的故障期输入。
4. **恢复不能由旧回执冒充。** 每个验证任务创建独立业务键，30 秒且至少 10 个完整创建/查询/取消流程；未知请求沿原键查证或续办，未查到回执不得直接记失败或新建另一个键。现代码已修独立命名空间，F12 有实际证据；整批实验仍需记录未决数而非只报 HTTP 可达。
5. **身份、审计与凭据。** caller 白名单必须建立在已经验证的传输身份上；stdio 自报 AIC 仅本地测试。正式 AMQPS、AMP 证书签名和 Monitor 验签需要真实链路。环境隔离修复只证明新启动路径，不替代对正式任务消息精确归档扫描。

## 打包和一键部署的实际依赖

当前源码导出是可审阅、可复现的增量源码 overlay：需先取得保留的原基线/SDK，再按清单复制源码和应用 patch；它没有捆绑私密证书、数据库密码、模型、原生二进制或 Python 环境。旧包验证不能覆盖之后新增源码。

原生 Windows 路径需要 PowerShell 7.4+（`Start-Process -Environment`）、Python 3.12 项目环境、独立 Postgres MCP 环境、官方 PostgreSQL/Nginx portable binaries、数据库初始化、各域环境文件及本机 ASCII 路径别名。已有自动生成私密环境的脚本仍应使用，不应将现成 `runtime/private` 打包。

容器路径需要可运行的 Docker/Compose、可达的镜像与 Python 依赖下载通道、独立环境文件和命名卷；代理镜像还需要本地 SDK、AMP 签名依赖、正式域证书/配置挂载、每域持久账本，以及仅运维域的 Docker socket。容器“镜像构建通过”和“已有身份启动 AMQPS 成功”是不同验收。代理平台 profile 不应在未协调时启动重复 AIC。

本次实际 WSL 拉取 Docker Hub 超时，不能把 `compose config` 通过写成部署成功。Windows 现有网络可访问 Registry；正在尝试官方 crane 下载镜像 tar 再导入 WSL，未改动 Mihomo 或主机代理路由。

## 云端边界和行动次序

用户排除的是额外 Linux 云主机依赖。Windows 本机的真实数据库、WSL Docker、正式平台连接、公开贡献材料、同机可复现实验、新环境冷启动和长期运行仍属于方案要求；不应全部放进“云端没条件”而跳过。
