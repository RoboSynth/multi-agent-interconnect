## 可复核的离线工具

`tools/prepare_team_upload.py` 只读明确源码目录、必要官方代码、轻量外部资料及固定的已完成结果。
它输出 `manifest.json` 和 `candidate-scan.json`，列每个候选的来源、目标路径、字节数、SHA256、分类和扫描结论；
实际匹配到本机活跃秘密或内嵌私钥的源码会进入 quarantine，不自动变成可上传文件。
带账号密码的示例 URL 单列 review_examples，不把测试示例误报成真实泄露，也不未经查看直接 stage。

```powershell
.\.venv\Scripts\python.exe tools/prepare_team_upload.py --output artifacts/team-upload-review-20261017 --include-closed-result eval/results/platform/container-postgres-mcp-20261017-order-fix-v2/results.json
```

扫描只报告文件、行号和类别，不回显实际秘密。PDF 记录来源与哈希，但没有做二进制文本扫描；公开规则来源与私密运行材料分开。
候选清单是本次盘点，后续仍有代码在变更；最终提交前须在冻结点重生成/比对，不能把旧哈希当最新版本。
无须把本机所有运行结果都放进 Git；大型原始实验包可独立归档，由团队仓库提供哈希与索引。

## 给根代理的 `.gitignore` 建议（本轮未修改）

1. 当前 `vendor/` 整目录忽略会漏掉真实改造的官方 SDK。最终团队仓库应显式纳入所需 SDK 源、许可和 schema；其余官方微服务可保留来源/版本说明按需获取。
2. 当前只列三种 `.venv`，建议统一 `.venv*/`，并覆盖 `**/private/`、实际 `*.env` / `.env*`、私钥/证书容器、`*.sqlite*` / `*.db`、浏览器会话和机器 PID/运行配置。
3. 继续忽略 `runtime/`、`tools/runtime/`、缓存和 `artifacts/`。已完成的脱敏结果复制为单独 `evidence/`，不要为了上传几份结果就放开所有 `output/` 或 `eval/results/`。
4. Git 忽略规则不是内容脱敏。根代理实际 stage 时使用审定清单，并检查 staged diff；本机原始配置和当前工作进程不随仓库搬迁。
