## 平台排行榜的实际口径（10-19 核对）

梧桐首页有公开的“梧桐智能体调用排行榜”，数据接口为 `https://wt.ioa.pub/internal/matched-stats/top?startAt=…&endAt=…&n=…`（只读、无需登录）。要点：

- 按单个 AIC 排名，单位是“任务”，数值 = 配对成功的 access 任务数 + message 任务数；统计窗口从 2026-09-24 00:00（北京时间）起，按小时汇总。
- 有四个榜：调用榜、被调用榜，各分“含内部调用”和“不含内部调用”。同一前缀（如 `BUPT.VTF97R.*`）智能体之间的调用在“不含内部调用”榜中计为 0，本队七个身份共用 `BUPT.8N4WSS` 前缀，彼此调用很可能被算作内部调用。
- 10-19 晚查询时本队七个 AIC 均不在任何榜上（日志尚未上报）。含内部调用的调用榜第一名约 5945 任务；不含内部调用榜中，大多数智能体只有十几次，主要来自平台方的调用。
- 赛规“访问频次排行榜”具体用哪个榜，需在 QQ 群确认。在此之前：巡检流量照常上报（计入含内部榜，也满足后台截图要求）；同时争取外部调用——体检智能体对外开放、允许平台/叮当以只读方式调用本队智能体。

### 运行机器（本地电脑不能 24 小时开机时）

“24 小时”是我们自定的稳定性目标，不是赛规条款。赛规要的是“访问数据详实”“运行稳定”，访问排名按与第一名的比值给分。电脑开着的时间越长，访问数越多。

- **首选：租一台国内云服务器，只用来常驻运行。** Ubuntu 22.04，2 核 4G，选国内机房（梧桐在国内），租到 10-30 即可，学生优惠通常很便宜。代码已经全部容器化，WSL 里跑通过；Windows 专用的保持唤醒代码有平台判断，Linux 上会自动跳过。迁移步骤：装 Docker → 拉取分支 → 拷贝七个身份的证书和 `runtime/private` 配置（只放这一台）→ `docker compose` 部署 NEW7 → 用 Linux collector 发送日志 → 在 Linux 上启动工作台和巡检调度，并设为 systemd 服务。正式身份只在云上运行，本地电脑改用本地通道开发，不能再启动正式身份。
- **次选：实验室或学校机房里一台能常开的机器**，做法同上。
- **都没有时：按时段运行。** 每天开机时启动巡检和日志发送，关机前用 `stop_when_idle` 正常停止。按 10 分钟一轮，每小时约 70 次调用，每天开 12 小时约 860 次。稳定性证据改为多个连续 8 小时以上的运行窗口，报告如实写明运行时段。
