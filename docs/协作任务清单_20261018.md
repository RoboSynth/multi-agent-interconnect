## 可以立即做的事

- A：检查现有协议、模型/种子/方法定义绑定与结构化终态对账，不启动新 45 格。旧 8192 容量失败与新 32768 单次容量验证分列；参数变化不能混成同批性能改进。
- B：围绕真实缺口新增最小离线故障路径检查；沿用已有锁、账本和 fence，不另建一套恢复框架。改 SDK 前先确认项目已携带的改造与[第三方声明](../THIRD_PARTY.md)。
- C：按现有脚本给出独立机器复现反馈、配置保留/失败提示问题的具体复现。隐藏 WSL 保持辅助目前仅本地部署；此前容器启动时间变化的原因未确认，不先按猜测更改系统服务。
- D：校对[资料导航](资料导航.md)和最新事实入口，标明历史材料日期；将真实观察、方案目标、离线测试和正式运行分开，复用当前安全证据，不上传原始消息或私密配置。

## 共享接口和合并顺序

1. B 持有 IFC、operation_id、epoch/term、产物语义等公共契约变更的协调权；A 先约定所需字段，避免独立修改同一接口。
2. A 持有评测源代码、结果 schema 与报告统计；D 使用其安全输出写材料，通过问题单提出统计需求，不并行改评测实现。
3. C 持有部署/配置/启动脚本；B 需要新挂载或域启动参数时先约定差异。A 的运行冻结期间不改冻结源码和配置。
4. 进度和导航由合并负责人集中更新；每个 PR 可先写自己的任务结果与证据，再合并为最新进度。新来者先提交小改动完成一次审阅流程。

任务记录至少包括：分支与基线提交、文件所有者、完成标准、实际测试/运行、证据位置、未完成项。真实故障由一次运行的所有者统一监督；健康、故障、E3 和持久工作台不得并行消费同一 AIC。
