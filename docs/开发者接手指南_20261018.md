# 开发者接手指南（2026-10-18）

`xiaomuxia` 使用自己的 GitHub 账号即可接手 [RoboSynth/multi-agent-interconnect](https://github.com/RoboSynth/multi-agent-interconnect)，已核实拥有管理员权限，包含拉取和推送。源码、方案、测试、改造后的 ACPs SDK/CLI、实验结果和材料都在仓库中。日常代码开发与本地业务运行不需要原开发者的 GitHub、Codex 或梧桐账号。

先按下面的顺序完成一次自己的开发闭环。详细命令集中在两份配套文档，避免从历史运行记录拼接配置。

## 接手顺序

1. 阅读[本地开发环境与操作](本地开发环境与操作_20261018.md)，用自己的 GitHub 登录克隆最新 `main`，建立开发分支，安装 Python 依赖并做相关离线检查。
2. 需要运行订单业务时，按同一文档准备自己的独立 Docker 项目，执行准备、配置检查、启动、业务验证和停止。生成器会创建本机随机密码，无需索取原开发者的数据库配置。
3. 需要浏览器工作台时，再安装文档中的本地 MCP 隔离环境，走 Windows native / local AIP stdio 路线；此路线同样不需要正式平台身份。工作台不是仅启动四个业务容器就会自动出现。
4. 需要模型或正式平台联调时，阅读[自有账号平台配置](自有账号平台配置_20261018.md)。本地 Qwen 可自行下载运行；正式七角色需要在自己的梧桐账号下登记身份、等待审核并签发自己的证书。
5. 从下面的待办中选择一个小任务，记录基线提交、改动、实际测试和剩余问题，推送自己的分支并创建 PR。

新手先完成第 1 步即可开始修改代码；第 2、3、4 步按任务需要选择。离线开发和四业务部署不需要等待平台审核。

## 账号与环境的对应关系

| 要做的事 | 自己需要准备的内容 | 是否需要原开发者账号 |
| --- | --- | --- |
| 克隆、修改、推送、PR | 已获权限的 `xiaomuxia` GitHub 账号；Git 使用自己的 HTTPS 登录或 SSH key | 不需要 |
| 阅读方案、分析历史实验、开发 UI 和协议、运行相关离线测试 | Python 3.12、项目虚拟环境及仓库依赖；UI 为仓库内静态资源 | 不需要 |
| 运行独立订单业务 | 自己的 Docker Engine/Compose 环境；生成自己的项目名、端口、密码和数据卷 | 不需要 |
| 运行 Windows 本地多智能体工作台 | 本地 PostgreSQL/Nginx、独立 postgres-mcp 环境及生成的本机配置 | 不需要；使用本地 `local-*` 标识 |
| 运行本地 Qwen | 自己下载的模型文件和 llama.cpp 服务；按模板配置回环地址 | 不需要；本地推理不使用付费 API key |
| 正式梧桐七角色联调 | 自己的平台登录、审核通过的七个身份、自有证书/私钥和信任链 | 不需要；GitHub 权限不代替平台审核 |
| 官方 Kafka/Monitor 验收 | 赛方实际提供的服务地址、CA/认证及访问权限 | 仍需向赛方取得接入资料；占位配置不能完成入库 |

各开发者在自己的电脑生成 `.venv`、`runtime/private/`、数据库、模型及证书；仓库内的模板给出字段和生成步骤。不要将参考快照中的 `<PROJECT_ROOT>`、历史 PID、旧端口或示例身份当作自己机器的实值。正式平台同一 AIC 的 Inbox 只能由一个运行者消费；新账号使用自己的七身份可避免撞用原身份。

## 协作和提交

在 GitHub 的 Issues/PR 中约定任务、分支和文件范围；公共 IFC、operation_id、epoch/term、回执字段先协调再改。数据库主备继续共享资源域账本，同一既有资源不能通过新命名空间绕过旧未决或重置任期。独立新资源才使用自己的隔离命名空间。

一个 PR 处理一个可验收事项，说明具体问题、修改后的行为、实际检查、证据相对路径及剩余限制。默认 `unittest discover` 的匹配模式会遗漏 `business_*_test.py`；完整测试命令及已知失败见配套环境文档。纯文档检查差异和链接，行为改动运行相关测试即可。

`SNAPSHOT-MANIFEST.json` 是各批文件的校验索引；不是依赖锁，也不是启动配置。团队直接提交可能先于清单更新，遇到缺项先对照 Git 提交，不覆盖队友文件。第三方来源和许可见 [THIRD_PARTY.md](../THIRD_PARTY.md)，历次发布记录见 [COLLABORATION.md](../COLLABORATION.md)。
