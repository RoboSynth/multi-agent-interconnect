## 接手顺序

1. 阅读[本地开发环境与操作](本地开发环境与操作_20261018.md)，用自己的 GitHub 登录克隆最新 `main`，建立开发分支，安装 Python 依赖并做相关离线检查。

3. 需要浏览器工作台时，再安装文档中的本地 MCP 隔离环境，走 Windows native / local AIP stdio 路线；此路线同样不需要正式平台身份。工作台不是仅启动四个业务容器就会自动出现。

5. 从下面的待办中选择一个小任务，记录基线提交、改动、实际测试和剩余问题，推送自己的分支并创建 PR。

新手先完成第 1 步即可开始修改代码；第 2、3、4 步按任务需要选择。离线开发和四业务部署不需要等待平台审核。

修改 SDK 时，先按[SDK 检查说明](../tools/sdk-suite/README.md)准备`.venv-sdk`，再在仓库根目录运行完整检查；它不需要原开发者账号或正式平台身份：

```text
python tools/sdk-suite/run_sdk_suite.py --repo-root . --output ../sdk-suite-run-01 --python .venv-sdk/Scripts/python.exe
```

输出路径每次使用新目录，失败日志和实际退出结果都会保留。[两次运行证据](../evidence/sdk-suite-reproducer-20261019/README.md)中，修复后的入口已覆盖仓库内独立venv；这组本地SDK检查不代替正式平台或完整业务部署验收。
