# 开发者接手指南

当前开发以[强基线](BASELINE.md)为起点。使用自己的 GitHub 账号、独立分支和本机环境；本地开发不需要原开发者的账户、平台身份或 SSH 私钥。

## 1. 取得代码

接受团队仓库邀请，用自己的账号访问 `RoboSynth/multi-agent-interconnect`。GitHub CLI 的认证独立于浏览器会话；核对账号后克隆自己有权访问的分支。

团队默认分支 `main` 以当前强基线为共同开发起点，`baseline/strong-20261020` 保留本次发布入口。新成员从 `main` 克隆并建立自己的分支：

```bash
git clone https://github.com/RoboSynth/multi-agent-interconnect.git
cd multi-agent-interconnect
git switch main
git pull --ff-only origin main
git switch -c dev/your-name-task
git rev-parse HEAD
```

已有检出先保存当前改动，再切换并更新 `main`；自己的未完成分支继续保留，不用重置或强推。后续通过 PR 合入 `main`。评审 ZIP 与开发仓库的关系见[仓库边界](REPOSITORY.md)。

## 2. 建立环境

- [完整环境与操作步骤](本地开发环境与操作_20261018.md)：Python、PowerShell、Docker、业务启动与停止。
- [测试环境](test_environment_20261019.md)：在当前检出安装依赖和 SDK，不借用另一个目录的 editable 安装。
- [Windows 原生工作台](../deploy/local-up.ps1)：首次准备依赖用 `-Install`，模型用 `-EnableLocalModel` 显式开启。
- [独立 Docker 部署](../deploy/ISOLATED.md)：使用自己的项目名、端口、路由和数据卷。

## 3. 验证与修改

先跑受改动影响的测试。业务恢复以独立 30 秒、10 个完整订单流程为准；接口返回 200 或进程还在不能代替业务验收。

当前算法对照使用[完整 60 格基线](../evidence/p5-local60-r3-20261020/README.md)。保留方法、种子、模型预算、计分定义和全部失败。改完验证逻辑后，不混合不同口径的部分结果。

SDK 自身检查从[SDK 测试入口](../tools/sdk-suite/README.md)运行；不要将它与项目单元测试数量相加当成同一套测试。

## 4. 平台联调与停机

正式联调使用[自己的身份与证书](自有账号平台配置_20261018.md)，参照 [NEW7](../deploy/NEW7.md)。同一身份不能被多台机器同时消费。真实故障实验需独立资源、新计划及明确范围。

本地停止按[完整停机操作](windows_local_shutdown_20261019.md)，云端使用[服务器手册](../deploy/SERVER.md)。只处理本次拥有的进程、群组和容器，保存原始结果与清理收据。

提交格式和文档维护统一遵循[协作约定](../COLLABORATION.md)。
