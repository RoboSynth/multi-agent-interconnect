1. 从团队仓库最新 `main` 建自己的分支，记录实际提交号；用 `SNAPSHOT-MANIFEST.json` 对照交付文件。不要直接修改其他人的运行目录。
2. 看[资料导航](资料导航.md)、[当前进度](开发进度_高分方案.md)、[P0 审计](P0完成审计_20261017.md)，再看自己工作包对应文档。旧审计初审行和历史报告不是新增需求。
3. 本机开发源目录与团队 Git 交付副本分开维护。接手后以自己检出的 Git 提交为基线；本轮新检出目录的安装检查固定在 `659b4b500751ca2419c14803eaa3443529716f57`，后续启动修复的最终提交号以仓库实际记录为准。
4. 团队专用 `COLLABORATION.md`、`.gitignore` 与 `THIRD_PARTY.md` 含交付规则和许可，勿用开发机版本整文件覆盖。

## 先做离线开发

建议 Python 3.12、PowerShell 7.4+。在自己的克隆目录中安装依赖：

```powershell
py -3.12 -m venv .venv
New-Item -ItemType Directory -Force artifacts | Out-Null
.\.venv\Scripts\python.exe -m pip install -r requirements-high-score.txt
.\.venv\Scripts\python.exe -m pip install "./vendor/ACPs-community/acps-sdk[amp-sign]"
```

依赖下载需要网络；工作台 UI 的 HTML/JS/CSS 已在 `demo-ui/`，不需要另建前端工程。CLI 开发需要时另安装 `./vendor/ACPs-community/acps-cli`。依赖版本见 [requirements-high-score.txt](../requirements-high-score.txt) 与 [requirements-lock.txt](../requirements-lock.txt)，第三方许可见 [THIRD_PARTY.md](../THIRD_PARTY.md)。

按改动选择相关离线测试，例如：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_native_preparation.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_workbench_model_config.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_platform_smoke.py
```

这些是可选择的检查入口，不要求每个改动跑完整测试树或真实 F10。纯文档检查差异和链接；行为变更补对应故障路径或契约检查，结果写明实际执行范围。

## 资源、模型与身份

本地资源启动是显式操作，见 [部署说明](../deploy/README.md) 和[本地验收](本地开发验收.md)。`deploy/local-up.ps1 -Install` 会安装依赖并准备、启动本机服务；先核对端口和既有实例，不在共享开发机上随意重跑。新检出目录仍使用默认本机端口，不能靠换目录隔离在线服务。默认不改变已有模型选择；`-EnableLocalModel` 才显式启用本地模型。团队默认使用本地 Qwen，不自动切换付费 API。

每位开发者自行持有私密配置、资源密码、EAB、身份/账户私钥和证书；模板可以复制，真实值不入 Git。离线开发不需要正式身份。正式平台联调由一次运行的所有者独占 AIC Inbox，同一身份不能在两台机器同时收消息；共享故障和修复实验先排期并明确资源范围。

现成模板包括 [部署环境](../deploy/.env.example)、[CLI 配置](../integration/acps-cli.example.toml)、[数据库网关](../domains/database/gateway.example.json) 和[巡检配置](../ops/schedule.example.json)。NEW7 七角色准备及隔离端口见 [NEW7.md](../deploy/NEW7.md)，不要把历史双智能体示例当作当前七角色部署入口。

## 分支与交付

按任务建立短分支，例如 `feat/e3-reconciliation`，一个 PR 处理一个可验收事项。先约定文件所有权，公共契约变更先同步；不要同时编辑同一份进度表。PR 写清触发问题、最终行为、实际检查、证据相对路径和剩余限制。共享集成由运行所有者统一执行并记录正常收尾，外部提交按项目负责人的发布安排进行。
