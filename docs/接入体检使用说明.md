# 接入体检使用说明

体检技能为 `aip.onboarding.check`。通过梧桐 ADP 按该技能发现服务，取其 ACS 的 AIC 和 AMQPS Inbox 端点，再用自己的 AIC 和证书邀请它加入 AIP 群组；调用前由提供方确认该服务在线且已开启对外元数据体检。

服务只查询目标 AIC 的公开 ACS/ADP 元数据，检查协议02.02、官方ACS结构、技能字段和AMQPS Inbox格式；不连接目标端点，不持有数据库/服务器凭据，不验证目标私钥或实际证书用途。证书用途仍需目标方本机检查，不能把元数据通过写成mTLS运行通过。

最小IFC任务：
```json
{"schema_version":"ifc/1.0","incident_id":"check-001","logical_task_id":"check-001:1","kind":"observe","tool":"aip.onboarding.check","args":{"target_aic":"替换为目标AIC","deep":false},"budget":{"deadline_ms":30000}}
```
返回 `facts[key=onboarding_report].value`，包含 `found/passed`、具体检查项及 `suggestions`。`tool_error`表示官方元数据查询失败，不能据此判目标配置错误。

本仓库的最小客户端默认只生成请求：
```powershell
python tools/onboarding_client.py --target-aic <目标AIC>
```
准备自己的私密caller.json，仅包含`leader:{aic,endpoint,cert,key}`、`trust_bundle`、`discovery_url`、`mq_auth_url`；证书路径可相对此配置文件。确认该调用身份没有其他消费者后，才实际运行：
```powershell
python tools/onboarding_client.py --target-aic <目标AIC> --service-aic <ADP返回的服务AIC> --config runtime/private/caller.json --output artifacts/onboarding-call-01 --execute
```
客户端会发现、描述确认、检查指定目标、正常关闭自建群组并保留日志。每次使用新输出目录；调用或关闭失败直接保留现场。

提供方只在体检域配置中显式设置`public_metadata_service:true`，保留自己的`allowed_leaders`、独立证书与日志目录，且不配置`env_file`。其他资源域拒绝该开关，默认仍只允许既有白名单。真实对外部署、官方往返和队外调用尚待执行；本轮只完成本地实现与离线验证。外部调用用`ops/longrun_status.py`的`--team-aic`列出七个本队身份后按接收端Start/taskId去重统计。

配置生成入口均支持显式`--public-onboarding`：`domains/setup_platform.py`会要求已有独立体检身份；`deploy/prepare_agents.py`须同时带`--include-onboarding`；完整隔离部署用`deploy/prepare_deployment.py --mode seven`。这些入口仅准备配置，实际启用需重新部署；不带开关时默认关闭，容器生成器会保留来源配置中已经显式开启的值。
