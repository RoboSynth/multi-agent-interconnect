# 用自己的账号接续开发

适用于 xiaomuxia 等团队开发者。GitHub 协作账号、梧桐注册账号和本地模型是三个独立事项：进入团队仓库即可改代码；离线检查与本地 Qwen 不需要梧桐或 OpenAI API 账号；正式 AMQPS 联调才需要自己的获批身份和证书。以下命令在自己的仓库根目录执行，不复用作者的 AIC、登录 token、EAB 或私钥。

## 1. 先做离线开发或本地模型开发

按[本地开发环境与操作](本地开发环境与操作_20261018.md)创建 Python 3.12 虚拟环境、`artifacts` 目录并安装依赖。按改动选择相关离线检查；此时不运行部署或平台命令。

Windows 本地 Qwen 使用项目内 llama.cpp/Vulkan 便携包，不需要 API key；首次 `setup` 会联网下载模型和运行程序。以下是开发者自行选择执行的模型操作，先确认自己的 8089 端口空闲：

```powershell
.\.venv\Scripts\python.exe tools/local_model.py setup
.\.venv\Scripts\python.exe tools/local_model.py start --context-size 32768
.\.venv\Scripts\python.exe tools/local_model.py status
.\.venv\Scripts\python.exe tools/configure_local_coordinator.py --enable-llm --model-base-url http://127.0.0.1:8089/v1 --model Qwen3-1.7B-Q8_0
```

本地配置保存为 `runtime/local-coordinator.json`；`--disable-llm` 使用规则模式，`--check` 仅校验配置。该配置入口只负责 `local-aip-stdio` 的模型选项，不用于修改正式梧桐协调者。配置成功不代表资源或工作台已启动。

只有准备运行本地业务时，才按[部署说明](../deploy/README.md)选择原生或隔离容器方案。Windows 原生一键入口为 `pwsh -NoProfile -File deploy/local-up.ps1 -Install -EnableLocalModel`：会安装依赖、准备数据库和网关并启动工作台；它不启动模型，默认本机端口也不因换目录而隔离。新检出目录、完整新机器与实际验收的区别见[本地接手验证](本地接手验证_20261018.md)。

已完成本地资源准备后，可用 `.\.venv\Scripts\python.exe -X utf8 tools/workbench_host.py --launch` 启动本机受控工作台。该 host 固定读取 `runtime/local-coordinator.json`、使用 8766，不运行 scheduler。关闭时从自己的 `runtime/workbench-server.json` 读取 `runtime_pid` 和 `session_nonce`，执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/workbench_host.py --stop --pid <自己的runtime_pid> --nonce <自己的session_nonce>
```

这是空闲关闭请求；须等对应 control directory 的 `finished.json` 确认正常关闭。不要用它关闭正式梧桐工作台，也不要复制作者的 PID/nonce。模型没有 `stop` 子命令，结束开发时另按自己启动的进程身份关闭。

## 2. 在自己的梧桐账号下登记七个角色

打开[官方 Registry](https://wt.ioa.pub/registry/)，注册/登录自己的账号，填写自己的提供者资料。在“我的智能体”中分别创建下表七个身份；初次 ACS 的 `aic` 留空，Inbox 使用 `amqps://wt.ioa.pub:5671/acps?inbox=inbox_{AIC}`，由平台批准后替换正式 AIC。独立实例按普通身份登记，不使用 entity derive。

| source.json 键 | 角色 | ACS skill id |
| --- | --- | --- |
| leader | 协调者 | incident.coordinate |
| application | 应用 | incident.application |
| verification | 业务验证 | incident.verification |
| database | 主数据库 | db.observe、db.act |
| database_backup | 备用数据库 | db.observe、db.act |
| ops | 运维 | ops.observe、ops.act |
| onboarding | 接入体检 | aip.onboarding.check |

ACS 使用协议 `02.02`、JSON 输入/输出、AMQP transport、`amqp:0.9.1` 能力和 mTLS；按本项目角色描述填写实际能力及自己的 provider。字段格式见[固定 ACS 规范](../vendor/ACPs-community/acps-specs/03-ACPs-spec-ACS/ACPs-spec-ACS.md)，本地角色描述见 `domains/setup_platform.py`。提交后等待逐角色审核通过，记录每个正式 AIC；不能把示例占位值当成获批身份。

也可用仓库内官方 CLI 提交自己已经填写的 ACS。先安装 CLI，并将公共配置复制到自己的私密目录；下例不把密码放进参数或 Git：

```powershell
.\.venv\Scripts\python.exe -m pip install ./vendor/ACPs-community/acps-cli
$private = Join-Path (Get-Location) 'integration/private/xiaomuxia'
New-Item -ItemType Directory -Force $private | Out-Null
$cli = '.\.venv\Scripts\acps-cli.exe'
$cliConfig = Join-Path $private 'acps-cli.local.toml'
if (-not (Test-Path $cliConfig)) { Copy-Item integration/acps-cli.example.toml $cliConfig }
& $cli --config $cliConfig auth login
& $cli --config $cliConfig auth whoami
```

登录行为由 CLI 配置决定：local 模式交互输入自己的账号密码；OIDC 模式使用浏览器设备登录。网页已登录不等于 CLI 已登录。token 和 CA account key 路径相对这份私密配置解析，不复用其他开发者的配置目录。对七份自己的 ACS 分别执行；`$agentId` 填 `save` 返回的草稿 UUID，不是 AIC：

```powershell
$acsFile = Join-Path $private 'acs/application.acs.json' # 自己已填写的本角色 ACS
& $cli --config $cliConfig agent save --acs-file $acsFile --no-ontology --json
$agentId = 'REPLACE_WITH_DRAFT_UUID_RETURNED_BY_SAVE'
& $cli --config $cliConfig agent submit --agent-id $agentId --json
& $cli --config $cliConfig agent check --acs-file $acsFile --json
& $cli --config $cliConfig agent sync --acs-file $acsFile --json
```

## 3. 用自己的 AIC 领取 EAB 并签发客户端证书

把[七身份模板](../integration/seven-identities.example.json)复制到 `integration/private/xiaomuxia/source.json`。替换七个不同的 AIC、各自精确 Inbox 和所有绝对文件路径。模板中的 `X:/REPLACE_WITH_YOUR_PRIVATE_DIRECTORY` 是 Windows 绝对路径占位，须换成自己目录；Linux 换成自己的绝对路径。`leader` 对应协调者；备用键是下划线 `database_backup`。

证书路径先填写将要生成的位置，目录由自己创建；审核通过后再签证。同时把自己 CLI 配置中 `[ca].trust_bundle_path` 和 `[mq].ca_cert_file` 改成 source.json 的同一绝对信任链路径，避免状态查询沿用示例目录而跳过 OCSP。以下每项都是官方平台操作，首次只执行一次并保留结果；错误时核对原因，不循环重新登记或重新领 EAB。

```powershell
$source = Join-Path $private 'source.json'
$identities = Get-Content -LiteralPath $source -Raw -Encoding UTF8 | ConvertFrom-Json
New-Item -ItemType Directory -Force (Split-Path $identities.trust_bundle) | Out-Null
foreach ($entry in $identities.agents.PSObject.Properties) {
    $role = $entry.Name; $agent = $entry.Value
    New-Item -ItemType Directory -Force (Split-Path $agent.cert),(Split-Path $agent.key) | Out-Null
    $eabFile = Join-Path $private "$role-eab.json"
    & $cli --config $cliConfig cert eab fetch --aic $agent.aic --output $eabFile
    if ($LASTEXITCODE -ne 0) { throw "EAB fetch failed for $role" }
    & $cli --config $cliConfig cert issue --aic $agent.aic --eab-file $eabFile --usage clientAuth --key-path $agent.key --cert-path $agent.cert --trust-bundle-path $identities.trust_bundle
    if ($LASTEXITCODE -ne 0) { throw "Certificate issue failed for $role" }
    & $cli --config $cliConfig cert status --aic $agent.aic --cert-path $agent.cert
    if ($LASTEXITCODE -ne 0) { throw "Certificate status failed for $role" }
}
```

EAB 含 `keyId`/`macKey`；身份私钥、ACME account key、CLI token 及资源密码留在自己的私密目录。证书状态查询不替代 AIC、clientAuth、有效期和私钥匹配检查；准备器也不会替你完成这些密码学检查。

## 4. 准备自己的七角色 profile，再显式联调

推荐当前 [ISOLATED 入口](../deploy/ISOLATED.md)，无需先运行原生 `setup_local.py`。下面的第一条只在新空目录生成配置、私密环境、路由和 target；第二条仅渲染检查。先安装 Docker/Compose v2；Windows 走 WSL 时需对应发行版及 Docker 已就绪，原生 Docker 模式省略 `--wsl`。

```powershell
.\.venv\Scripts\python.exe deploy/prepare_deployment.py --mode seven --identity-file integration/private/xiaomuxia/source.json --output runtime/private/xiaomuxia-seven --project incident-pilot-xiaomuxia --app-v1-port 58081 --app-v2-port 58082 --order-port 58088 --reply-drop-port 58090 --wsl Ubuntu-22.04
pwsh -NoProfile -File deploy/up.ps1 -DeploymentFile runtime/private/xiaomuxia-seven/deployment.json -ValidateOnly
# 确认自己项目、端口及七个 AIC 均空闲后，才启动自己的十个容器：
pwsh -NoProfile -File deploy/up.ps1 -DeploymentFile runtime/private/xiaomuxia-seven/deployment.json
.\.venv\Scripts\python.exe deploy/verify.py --deployment-file runtime/private/xiaomuxia-seven/deployment.json --output artifacts/xiaomuxia-seven-h00-first
```

端口只是示例，先确认自己机器上可用。业务 H00 不向平台发任务；启动六域容器会连接自己的 Inbox。生成配置位于 `runtime/private/xiaomuxia-seven/domains/`，协调者为 `coordinator/config.json`。每域只挂本域材料，主备共享本项目账本，项目隔离不允许同 AIC 双消费者。旧 `NEW7.md` 是作者实例与历史运行说明；不要复用其 AIC、项目、卷、私密路径或旧 E1 revision3。旧 E1 不能在当前源树直接执行，见[最新回执修复与冻结边界](original_receipt_correctness_20261018.md)。

启动器不启动宿主协调者。确认六域就绪后，在**单独的前台 PowerShell 子进程**启动自己的协调工作台；以下白名单只作用于该子进程，保留网络代理，清除资源凭据，不加载 compose.env：

```powershell
pwsh -NoProfile -Command {
    $allowed = @('SYSTEMROOT','WINDIR','COMSPEC','PATH','PATHEXT','TEMP','TMP','APPDATA','LOCALAPPDATA','USERPROFILE','PROGRAMFILES','PROGRAMFILES(X86)','PROGRAMDATA','SYSTEMDRIVE','HOMEDRIVE','HOMEPATH','USERNAME','OS','NUMBER_OF_PROCESSORS','PROCESSOR_ARCHITECTURE','HTTP_PROXY','HTTPS_PROXY','ALL_PROXY','NO_PROXY')
    Get-ChildItem Env: | Where-Object { $_.Name -notin $allowed } | ForEach-Object { Remove-Item -LiteralPath "Env:\$($_.Name)" }
    & .\.venv\Scripts\python.exe -X utf8 workbench_server.py --config runtime/private/xiaomuxia-seven/domains/coordinator/config.json --output artifacts/xiaomuxia-platform --port 8877
}
```

访问 `http://127.0.0.1:8877`，先核对实际模式、连接、参与者及配置。此入口默认不启用模型、不自动巡检、不注入故障。`tools/workbench_host.py` 只适用于本地 stdio，不支持这里的正式配置。关闭前确认无处理中的事故、无待审批/在途任务，再在这个前台窗口按 Ctrl+C，等待正常退出及自有群组关闭；不要按 UI 健康状态推断已收尾。新的正式故障/接管要重新准备版本与运行范围，不能复用旧实验授权。平台 Kafka/Monitor 配置另向平台取得，梧桐登录不自动提供这些参数。

## 5. 保留数据收尾

七角色协调者按上节正常关闭后，在原仓库根目录、原 Docker context/daemon 下停自己的六域，再停四业务。下面复用部署器的 manifest 校验、Compose 参数和环境过滤；Windows 直接 Docker 与 manifest 指定的同一 WSL 发行版均由现有 `compose_command` 处理，包括 `/mnt/<盘符>/...` 路径转换。不要换到另一个发行版执行，也不要修改或加载 compose.env：

```powershell
@'
import os, subprocess
from deploy.prepare_deployment import load_deployment, compose_command, GENERATED_ENV_KEYS
manifest = load_deployment("runtime/private/xiaomuxia-seven/deployment.json")
if manifest["mode"] != "seven":
    raise SystemExit("Expected this developer's seven-role deployment")
scope = compose_command(manifest, sanitized=True)
environment = {k: v for k, v in os.environ.items()
               if not k.upper().startswith("COMPOSE_") and k.upper() not in GENERATED_ENV_KEYS}
print("Stopping project:", manifest["project"], "WSL:", manifest["wsl_distro"])
subprocess.run(scope + ["ps", "--all"], env=environment, check=True)
for services in (("application-agent", "verification-agent", "onboarding-agent", "database-agent", "database-backup-agent", "ops-agent"),
                 ("nginx", "app-v1", "app-v2", "postgres")):
    subprocess.run(scope + ["stop", "--timeout", "30", *services], env=environment, check=True)
subprocess.run(scope + ["ps", "--all"], env=environment, check=True)
'@ | .\.venv\Scripts\python.exe -X utf8 -
```

这是文档中组合现有函数的停止操作，不是新增的统一 `down` CLI。确认十个服务均已停止，并保留退出码和日志；`stop` 命令成功不证明每个进程都在宽限时间内自行退出。容器、网络、订单卷、主备账本和原配置均保留，不加 `-v`，不删除卷或重新生成密码。不关闭其他项目或其他人的 WSL/Docker。

如果自己启动过本地 Qwen，Windows 下按本检出的记录、可执行文件、模型文件及监听 PID 核实后，只关闭这个 llama-server。该工具没有正常停止接口，下面明确是受控终止，不是全杀同名模型进程；任何核验失败都停下检查：

```powershell
$record = Get-Content tools/runtime/local-model/server.json -Raw -Encoding UTF8 | ConvertFrom-Json
$modelPid = [int]$record.pid
$expectedExe = (Resolve-Path tools/runtime/local-model/b11707/llama-server.exe).Path
$expectedModel = (Resolve-Path tools/runtime/local-model/Qwen3-1.7B-Q8_0.gguf).Path.Replace('\','/')
$identity = Get-CimInstance Win32_Process -Filter "ProcessId = $modelPid"
$port = ([uri]$record.base_url).Port
$listeners = @(Get-NetTCPConnection -State Listen -LocalPort $port -ErrorAction Stop)
if (-not $identity -or $identity.ExecutablePath -ne $expectedExe -or
    $record.model -ne 'Qwen3-1.7B-Q8_0' -or $port -ne 8089 -or
    $identity.CommandLine.Replace('\','/') -notmatch [regex]::Escape($expectedModel) -or
    $identity.CommandLine -notmatch '--alias\s+Qwen3-1\.7B-Q8_0(?:\s|$)' -or
    $identity.CommandLine -notmatch '--port\s+8089(?:\s|$)' -or
    $listeners.Count -eq 0 -or @($listeners | Where-Object OwningProcess -ne $modelPid).Count) {
    throw 'Recorded PID, executable, command line or listener does not match this model'
}
$ownedModel = Get-Process -Id $modelPid -ErrorAction Stop
Stop-Process -InputObject $ownedModel -ErrorAction Stop
Wait-Process -InputObject $ownedModel -Timeout 15 -ErrorAction Stop
Get-NetTCPConnection -State Listen -LocalPort 8089 -ErrorAction SilentlyContinue
```

保留 server.json 和 server.log 作为历史记录，不把旧 PID 当成下次启动的身份凭据。这里只关闭自己的模型；原生业务及本地工作台另按前述入口收尾。
