# 体检 ACS 的文本模式声明更新

体检的新运行时已实现普通文本输入和中文结果说明；当前已批准 ACS 仍只声明 `application/json`。代码部署与 Registry 声明更新是两项独立工作，下面的资料尚未提交平台。

## 已核实的限制

2026-10-20 无登录读取[官方 OpenAPI](https://wt.ioa.pub/registry-server/openapi.json)：`PUT /api/v1/agent/client/{agent_id}` 的说明为“审核通过的不能再更新（仅限 CLIENT 角色）”。官方 CLI 的 `agent upsert` 也是查同名同版本记录后调用此 PUT，不具备修改已批准记录的额外权限。ATR 的公开 ACS 接口只有读取入口。

因此，保留现有 AIC 的最小处理方式是请 Registry 管理员按平台支持的流程更新这一条已批准记录，或为它恢复受控编辑流程。普通用户登录会话不能解决权限限制。不要通过删除、重建或新版本注册来尝试绕过，这些操作可能改变身份及证书绑定。

## 管理员处理包

仅针对体检身份：`1.2.156.3088.1.BUPT.8N4WSS.46ZKB8.5GNEFA.03KF`，名称“跨域接入体检智能体”，版本 `1.0.0`。

[公开对比包](onboarding-acs-text-20261020/)包含：

- `onboarding.approved.before.acs.json`：从公开 ATR 读取的现行完整 ACS。
- `onboarding.text-modes.proposed.acs.json`：仅追加文本模式的建议完整 ACS。
- `onboarding.text-modes.patch.json`：供审阅的四项 JSON Patch；它不是 Registry 支持 PATCH 的声明。
- `observation.json`：公开来源、读取时间、API 限制和变更范围证明。
- `discovery-request.json`：按该 AIC 精确查询、包含全部在线状态的只读请求。
- `offline-validation.json`：现行与建议 ACS 均通过官方固定 schema 和 SDK 结构检查；不代表平台已更新。

四项变更均为在原数组末尾追加 `text/plain`，保留 `application/json`：

| 位置 | 新增值 |
| --- | --- |
| `defaultInputModes` | `text/plain` |
| `defaultOutputModes` | `text/plain` |
| 技能 `aip.onboarding.check` 的 `inputModes` | `text/plain` |
| 同一技能的 `outputModes` | `text/plain` |

建议文件的 AIC、name、version、provider、endPoints、安全方案、技能 ID 及其余全部字段均与读取快照一致。不要使用重新生成的草稿覆盖已批准记录的权威 provider 或端点。

## 最小处理与核验步骤

1. 部署负责人先补齐[使用说明](接入体检使用说明.md)中的新运行时上线版本和证据，确认该运行时已支持文本，再更新公开声明。
2. 管理员重新读取该 AIC 当前 ACS，与包内快照比较；若期间已有变更，将四项追加操作应用到最新记录，保留其余字段。只更新现有体检身份。
3. 完成平台正常发布/同步流程，记录实际操作时间和审核状态；不得只以保存成功认定 Discovery 已更新。
4. 读取[该 AIC 的公开 ATR ACS](https://wt.ioa.pub/registry-server/acps-atr-v2/acs/1.2.156.3088.1.BUPT.8N4WSS.46ZKB8.5GNEFA.03KF)，再向[官方 Discovery](https://wt.ioa.pub/discovery/acps-adp-v2/discover)发送包内 `discovery-request.json`。两处都应保留原 AIC/provider/endPoints，并在四个位置出现两种模式；分别保存新证据。
5. 最后由使用自己身份的队外调用方发送一次真实文本体检，检查 AIP 生命周期、中文回复和双方 access 日志。仍未进行的项继续标为待验证。

当前状态：公开 ACS 更新待管理员处理；新运行时云端上线及真实队外往返结果见使用说明中的待填表。本说明及对比包不包含登录凭据，也未触发 Registry 写入、群消息或身份启动。
