# 模型 API 与 Agent 开源案例对照

核查日期：2026年10月15日。范围是“我们的开源软件调用模型 API，现场完成实用任务”，并纳入用户新提出的 Agent 方向。下列26项包括终端产品、开发工具和可复用组件，不代表26个成熟商业产品，也不是本赛事获奖名单。

能力依据官方仓库、文档和原始论文；本轮未安装运行这些项目。README里的能力声明与实际效果分开看，未以星标数代替用户留存或质量证据。表中的“启示”是选题判断，不能当作已验证的技术空白。

| 编号 | 项目与原始来源 | 用户任务或交付物 | 模型之外已有的软件贡献 | 对我们选题的约束或启示 |
| --- | --- | --- | --- | --- |
| 01 | [PDFMathTranslate](https://github.com/PDFMathTranslate/PDFMathTranslate) | 外文科研PDF变成保留排版的译文或双语PDF | 文档解析、公式和布局处理、重排、用户入口与导出 | 值得学习“模型能力＋完整成品交付”。继续做翻译，需要明确超越已有功能；OCR等部分能力仍标为实验性 |
| 02 | [Data Formulator](https://github.com/microsoft/data-formulator) | 多来源数据探索、转换、可视化 | 交互图表、数据转换、分析历史与多来源连接 | 自然语言分析表格已经有强替代；用户少核对、少返工才有新价值 |
| 03 | [DocETL](https://github.com/ucbepic/docetl) | 大批文本抽取、归纳、分类和整理 | 语义算子、并行流水线、自动优化、DocWrangler交互界面 | “材料到总表”“多步处理”“自动优化”都有先例 |
| 04 | [SheetAgent](https://github.com/hvithalani/sheetagent) | 输入表、处理说明及可选成品示例，形成可重复执行的表格加工步骤 | 生成Power Query及pandas代码，对照示例验证，保存处理方案 | “学一次、下次不调用模型”已经有人公开实现。仓库规模较小，本轮未验证其泛化表现，不能把宣传中的持续有效当成事实 |
| 05 | [Unstract](https://docs.unstract.com/unstract/editions/open_source_edition/) | 非结构化文档转结构化业务数据 | 文档处理平台及流水线；商业版本还提供人工质量审核 | 需要区分开源版、商业版；官方版本说明把Human Quality Review列为商业能力 |
| 06 | [LangExtract](https://github.com/google/langextract) | 按给定结构从文本抽取信息并定位原文 | 原文跨度关联、示例定义结构、长文本处理与可视化 | 这是组件案例；“每个结果带来源”有复用价值，但不是独特创新 |
| 07 | [Presenton](https://github.com/presenton/presenton) | 材料或描述生成可编辑演示文稿 | 模板与设计复用、编辑界面、PPTX/PDF输出 | “AI做PPT＋可以编辑”已经不足以区分作品 |
| 08 | [Open Notebook](https://github.com/lfnovo/open-notebook) | 多种资料形成笔记、问答和播客 | 资料管理、引用、上下文选择、转换流程与接口 | 普通知识库问答竞争充分；应明确用户最终拿走什么成果 |
| 09 | [Paperless-AI](https://github.com/clusterzx/paperless-ai) | 已有档案系统自动分类、命名、打标签与检索 | 文档系统集成、自动处理、人工处理和规则 | 当前README明确不维护，作者同时提到上游计划集成AI；仅补通用AI功能可能被上游覆盖，不能据此断言上游所有稳定版已经上线 |
| 10 | [Next AI Draw.io](https://github.com/DayuanJiang/next-ai-draw-io) | 描述、图片或资料生成并修改可编辑图示 | 原生画布、选区编辑、版本比较和恢复、导出 | “能对话改图、能撤销、能编辑”已经存在；可研究复杂连续修改时的正确性与布局稳定 |
| 11 | [OpenWhispr](https://github.com/OpenWhispr/openwhispr) | 在当前应用语音输入或修改文本 | 全局入口、清理与命令、选中文本修改、上下文集成 | 高频用途明确，竞争也强；可研究意图识别及纠错总成本，不能只加一个语音入口 |
| 12 | [VideoCaptioner](https://github.com/WEIFENG2333/VideoCaptioner) | 视频生成字幕、校正、翻译及合成 | 字幕编辑、断句、批处理、上下文辅助 | 单做字幕翻译或术语辅助已有直接对手 |

| 14 | [ViDove](https://github.com/pigeonai-org/ViDove) | 长视频翻译和双语字幕 | 视觉与听觉信息结合、记忆、词典及评测资源 | 可借鉴多模态处理和公开评测，但不能把多Agent校对直接当原创 |

| 18 | [Toonflow](https://github.com/HBAI-Ltd/Toonflow-app) | 剧本、分镜、角色素材与漫剧制作 | 创作资产管理、画布和生成工作流 | 一键漫剧已有直接项目。当前官方仓库标MIT，旧版本条款不同，复用时应固定版本核对 |
| 19 | [Skyvern](https://github.com/Skyvern-AI/skyvern) | 浏览器中的查找、录入、下载和工作流 | 浏览器工具、抽取、验证、循环及流程运行 | “会点网页＋验证结果”已有；托管服务能力不能全部归给开源核心 |

| 25 | [Hercules](https://github.com/test-zeus-ai/testzeus-hercules) | 自然语言测试步骤驱动应用测试 | UI/API执行、验证、测试数据及工具调用 | 普通“AI测试员”已有直接对手；复现、误报及业务约束核验更值得比较 |

**两个值得学习的系统研究案例。** PDFMathTranslate进入[EMNLP 2025系统演示论文集](https://aclanthology.org/2025.emnlp-demos.71/)；ViDove的[EMNLP 2025论文](https://aclanthology.org/2025.emnlp-demos.17/)介绍长视频字幕系统与DoveBench。它们支持“使用现成模型仍可以做出系统方法和评测贡献”这一判断；不是AIC国一、国二获奖证据，也不能用来估算获奖概率。

**三条会直接影响创新表述的证据。**

- [DocWrangler论文](https://arxiv.org/abs/2504.14764)已有用户注释、根据注释修改提示和分解复杂操作。因此“用户纠正一条，系统学习改进”必须进一步具体化。
- [Next AI Draw.io Issue #655](https://github.com/DayuanJiang/next-ai-draw-io/issues/655)提出复杂图重叠与布局约束需求；[Issue #882](https://github.com/DayuanJiang/next-ai-draw-io/issues/882)记录多图工作时覆盖画布的问题。这些是用户报告线索，未在当前版本复现，不能直接宣称缺陷现在仍存在。
- [OpenWhispr Issue #1412](https://github.com/OpenWhispr/openwhispr/issues/1412)提供中英混说被意外翻译、语气与自我纠正混淆的需求线索。是否普遍、是否已修复都需要实测。

**其他必须纳入的替代方案。**

- 普通表格整理：[Power Query](https://learn.microsoft.com/power-query/combine-files-overview)已经可以合并同结构文件。规则确定的工作不需要强行引入Agent。
- 操作录制：[Power Automate](https://learn.microsoft.com/en-us/power-automate/desktop-flows/recording-flow)已经能录制桌面及网页操作。
- 开源应用执行：[Pinokio](https://desktop.pinokio.co/docs/)已有应用发现、启动和Agent调用路径；[RepoLaunch](https://github.com/microsoft/RepoLaunch)研究自动构建和测试。软件安装器不能自动等同于任务执行创新。
- 接口测试：[Schemathesis](https://schemathesis.readthedocs.io/en/stable/)已有有状态测试；[KAT](https://arxiv.org/abs/2407.10227)研究依赖感知的LLM接口测试；[RESTifAI](https://arxiv.org/abs/2512.08706)及其[代码](https://github.com/casablancahotelsoftware/RESTifAI)涉及模型驱动的接口流程和业务规则测试。
- 教程制作：[Descript](https://www.descript.com/screen-recording)和[Guidde](https://www.guidde.com/)是用户可选择的商业替代。即使我们计划开源，也应比较它们的实际交付能力。

本轮不从这些案例推出“某方向没有人做”。更可靠的结论是：要选择具体工作，把已有系统当作起点和比较对象，再证明新增机制确实让用户更省事。
