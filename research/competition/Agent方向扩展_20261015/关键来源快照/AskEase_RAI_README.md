# Responsible AI Transparency Documentation - AskEase

## Overview

AskEase is an NVDA (NonVisual Desktop Access) plugin that is designed to enhance tool usage and learning for screen reader users.

### What Can AskEase Do

AskEase was developed to function as an on-demand AI assistant that provides step-by-step, screen reader user-friendly guidance for computer use.

NVDA (NonVisual Desktop Access) is a free, open-source screen reader that enables blind and visually impaired users to access computers by reading screen content aloud. While NVDA excels at announcing interface elements, it cannot provide contextual guidance on how to complete tasks or troubleshoot problems. AskEase addresses this gap by automatically collecting and managing multiple sources of context to enhance situational awareness. This context management allows it to analyze the current interface, understand user challenges, and infer user intent. AskEase delivers precise, situational-specific guidance.

A detailed discussion of AskEase, including how it was developed and tested, can be found in our paper.

### Intended Uses

AskEase is best suited for screen reader users who face steep learning curves and frequent obstacles in computer use.

AskEase is being shared with the research community to facilitate reproduction of our results and foster further research in this area.

AskEase uses a bring-your-own-model approach, requiring users to configure their own LLM API. Therefore, users need to have relevant technical knowledge to set up and use the system.

Additionally, since AI-generated guidance may be inaccurate, users should have the ability to evaluate the effectiveness of actions suggested by AI.

### Out-of-Scope Uses

Screen readers, in general, are not well suited for tasks requiring interaction that relies primarily on mouse movements or purely visual cues. AskEase does not address this problem.

We do not recommend using AskEase in commercial or real-world applications without further testing and development. It is being released for research purposes.

AskEase was not designed or evaluated for all possible downstream purposes. Developers should consider its inherent limitations as they select use cases, and evaluate and mitigate for accuracy, safety, and fairness concerns specific to each intended downstream use.

Without further testing and development, AskEase should not be used in sensitive domains where inaccurate outputs could suggest actions that lead to injury or negatively impact an individual's legal, financial, or life opportunities.

We do not recommend using AskEase in the context of high-risk decision making (e.g. in law enforcement, legal, finance, or healthcare).

## How to Get Started

To begin using AskEase, download the add-on from the GitHub Releases page.

Once AskEase is installed as an NVDA add-on, users interact with it through keyboard shortcuts:

- **Contextual Question & Answer**: `NVDA+Ctrl+O`
- **Adaptive support**: `NVDA+Ctrl+D`
- **Screen description**: `NVDA+Ctrl+J`
- **Previous step**: `NVDA+Ctrl+UpArrow`
- **Next step**: `NVDA+Ctrl+DownArrow`

## Evaluation

AskEase was evaluated on its ability to provide step-by-step guidance for screen reader users and to assist them in learning and using computers more effectively.

A detailed discussion of our evaluation methods and results can be found in our paper.

### Evaluation Methods

We used accuracy, latency and cost to measure AskEase's performance using Windows Agent Arena dataset.

The model used for evaluation was GPT-5. For more on this specific model, please see [GPT-5 document](https://openai.com/index/introducing-gpt-5/).

Besides, we conducted a within-subject study with 12 screen reader users to evaluate the effectiveness of AskEase compared to their usual tools (e.g., search engines or AI assistants). The evaluation was based on task completion and users' perceived workload.

Results may vary if AskEase is used with a different model based on its unique design, configuration, and training.

### Evaluation Results

At a high level, we found that AskEase performed strong accuracy, completing 96.6% of tasks with up to three Adaptive Support rounds, and maintained low latency and minimal API cost. The user study also showed that AskEase improved task completion rates while reducing perceived workload, including physical demand, effort, and frustration.

## Limitations

AskEase was developed for research and experimental purposes. Further testing and validation are needed before considering its application in commercial or real-world scenarios.

AskEase was designed and tested using the English language. Performance in other languages may vary and should be assessed by someone who is both an expert in the expected outputs and a native speaker of that language.

Outputs generated by AI may include factual errors, fabrication, or speculation. Users are responsible for assessing the accuracy of generated content. All decisions leveraging outputs of the system should be made with human oversight and not be based solely on system outputs.

AskEase inherits any biases, errors, or omissions produced by its base model. Developers are advised to choose an appropriate base LLM/MLLM carefully, depending on the intended use case.

AskEase is model agnostic, users are required to bring their own AI service to use the add-on. For research and evaluation, we used the GPT-5 model. See [GPT-5 document](https://openai.com/index/introducing-gpt-5/) to understand the capabilities and limitations of this model.

There has not been a systematic effort to ensure that systems using AskEase are protected from security vulnerabilities such as indirect prompt injection attacks. Any systems using it should take proactive measures to harden their systems as appropriate.

## Best Practices

Better performance can be achieved by using state-of-the-art multimodal large language models and employing RAG to retrieve relevant documents, thereby enhancing AskEase. The code repository also includes scripts to set up a RAG server, allowing users to optionally start the server and configure RAG-related content. This advanced, optional feature can further improve the accuracy of AskEase's responses.

We strongly encourage users to use LLMs/MLLMs that support robust Responsible AI mitigations, such as Azure Open AI (AOAI) services. Such services continually update their safety and RAI mitigations with the latest industry standards for responsible use. For more on AOAI's best practices when employing foundations models for scripts and applications:

- [What is Azure AI Content Safety?](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/overview)
- [Overview of Responsible AI practices for Azure OpenAI models](https://learn.microsoft.com/en-us/legal/cognitive-services/openai/overview)
- [Azure OpenAI Transparency Note](https://learn.microsoft.com/en-us/legal/cognitive-services/openai/transparency-note)
- [OpenAI's Usage policies](https://openai.com/policies/usage-policies)
- [Azure OpenAI's Code of Conduct](https://learn.microsoft.com/en-us/legal/cognitive-services/openai/code-of-conduct)

Users are reminded to be mindful of data privacy concerns and are encouraged to review the privacy policies associated with any models and data storage solutions interfacing with AskEase.

It is the user's responsibility to ensure that the use of AskEase complies with relevant data protection regulations and organizational guidelines.

Developers should follow transparency best practices and inform end-users they are interacting with an AI system.
