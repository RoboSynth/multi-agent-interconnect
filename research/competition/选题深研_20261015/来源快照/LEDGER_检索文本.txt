F.1   LEDGER Algorithm Details
We provide detailed algorithms for the three core components of LEDGER: semantic graph construction,
dependency-aware context retrieval, and incremental consistency verification.
F.1.1 Semantic Graph Construction
Algorithm 1 describes how LEDGER constructs and maintains the semantic dependency graph.

Algorithm 1 Semantic Graph Construction
 1: Input: Document D, Previous graph G = (V, E)
 2: Output: Updated graph G′ = (V ′ , E ′ )
 3:
 4: V ′ ← ParseSemanticUnits(D) {Extract sections, paragraphs, equations, figures}
 5:
 6: // Step 1: Build explicit reference edges
 7: Eexplicit ← ∅
 8: for each node vi ∈ V ′ do
 9:   refs ← ExtractReferences(vi ) {e.g., "Theorem 2", "Equation (5)", "Figure 1"}
10:   for each reference r in refs do
11:      vj ← ResolveTarget(r, V ′ )
12:      Eexplicit ← Eexplicit ∪ {(vi , vj , REFERENCES)}
13:   end for
14: end for
15:
16: // Step 2: Build implicit reference edges
17: Eimplicit ← ∅
18: anaphora ← DetectAnaphoricExpressions(V ′ ) {e.g., "this bound", "the lemma"}
19: for each (vi , expr, vj ) in anaphora do
20:   Eimplicit ← Eimplicit ∪ {(vi , vj , DEPENDS)}
21: end for
22:
23: // Step 3: Build semantic dependency edges
24: Esemantic ← ∅
25: for each node vi ∈ V ′ do
26:    vi .embedding ← Embed(Summary(vi )) {DistilBERT embeddings}
27: end for
28: for each pair (vi , vj ) where i ̸= j do
29:   sim ← CosineSimilarity(vi .embedding, vj .embedding)
30:   if sim > θ and no explicit/implicit edge exists then
31:      Esemantic ← Esemantic ∪ {(vi , vj , RELATED)}
32:   end if
33: end for
34:
35: E ′ ← Eexplicit ∪ Eimplicit ∪ Esemantic
36: return G′ = (V ′ , E ′ )


   The algorithm constructs a semantic graph in three steps. First, it extracts explicit references through
pattern matching for citations like “Theorem 2”, “Equation (5)”, and “Figure 1” (lines 6-13). Second,
it detects implicit references through coreference resolution to identify anaphoric expressions like “this
bound” or “the lemma above” (lines 14-18). Third, it computes semantic embeddings using DistilBERT
and connects nodes with high cosine similarity (θ = 0.7) that lack explicit connections (lines 19-28). The
                                                      10641
graph construction completes in 2-3 seconds for a typical 50-page paper with 150 semantic units, while
incremental updates after edits complete in under 200ms by reprocessing only modified nodes.
F.1.2 Dependency-Aware Context Retrieval
Algorithm 2 describes how LEDGER efficiently retrieves relevant context for each edit operation.
   The algorithm retrieves context in four steps. First, it identifies target nodes either through explicit
mentions (e.g., “Section 3.2”) or semantic similarity for ambiguous instructions (lines 4-11). Second, it
expands to include all nodes connected by dependency edges, capturing both upstream context (what the
target relies on) and downstream impacts (what depends on the target) (lines 12-16). Third, it prioritizes
nodes using an additive scoring scheme: direct targets (100 points), explicit references (50 points, critical
for consistency), implicit dependencies (30 points), and semantic relations (10 points, optional context)
(lines 17-28). Fourth, it packs content in priority order until the token budget B is exhausted (lines 29-38).
This approach typically retrieves 10-15% of document tokens while ensuring all critical dependencies are
included, as demonstrated in the Appendix example where only 1,200 of 10,000 tokens were needed.
F.1.3 Consistency Verification
Algorithm 3 describes how LEDGER validates document consistency after edits.

30:      score[vi ] ← score[vi ] + 30 {Implicit dependency}
31:   end if

33:      score[vi ] ← score[vi ] + 10 {Semantic similarity}
34:   end if
35: end for

43:       C ← C ∪ {ci }
44:       tokens ← tokens + |ci |
45:   else

47:   end if
48: end for

17:      new_term ← ExtractTerminology(vi .after)
18:      if orig_term ̸= new_term then
19:         V ← V ∪ {(TERM_CHANGE, vi , vj , orig, new)}
20:      end if
21:   end for
22: end for
23:
24: // Check 3: Semantic coherence
25: for each vi ∈ Nmod do
26:   enew ← Embed(Summary(vi .after))
27:   for each (vi , vj , RELATED) ∈ E do
28:      sim ← CosineSimilarity(enew , vj .embedding)
29:      if sim < θmin then
30:         V ← V ∪ {(SEM_DRIFT, vi , vj )}
31:      end if
32:   end for
33: end for
34:
35: // Update graph incrementally
36: G′ ← G
37: for each vi ∈ Nmod do
38:   Remove old edges incident to vi from G′
39:   Recompute edges for vi using Algorithm 1
40:   Add new edges to G′
41: end for
