# 内容重编：事实与证据

整理日期：2026-10-30。素材根目录为本文件的上一级“演示视频”。本文供重写口播、绘制机制图和核对结果卡使用；事实取自 2026-10-29 两次录像所绑定的运行记录。

## 1. 观众应当看懂的故事

订单业务发生异常，系统分别检查入口、应用和数据库。它发现入口仍指向旧版本，同时数据库只读。运维智能体恢复正确入口；数据库智能体经过审批恢复写入；应用智能体重建连接池。最后由业务验证智能体实际创建、查询并取消订单，确认恢复。

第二个案例中，数据库执行智能体已经完成修改，却在提交结果前退出。协调者收到超时结果。备用执行智能体接收任务与已有操作记录，复用已完成结果，跳过同一修改，再继续应用恢复和业务验证。

这两段分别说明“运维、应用和数据库智能体怎样协作完成恢复”和“执行进程退出后怎样接着做”。

## 4. 中断接管：为什么要先核对已完成的操作

本次中断发生在数据库修改已记入操作记录、结果尚未向协调者提交时。主执行智能体退出，协调者等待超时后让备用接手；备用先读取操作记录。

| 关键事实 | 直接证据 | 剪辑可以怎么呈现 |
|---|---|---|
| 退出对象是数据库主执行智能体的工作进程 | `V4-takeover/primary-trace.jsonl` 第 4 条：`event=experiment_worker_crash`、`crash_point=after_applied`、`exit_code=83`；`result.json` → `worker_exit_and_mcp.actual_exit_code=83` | “执行智能体中途退出” |
| 修改已经记账，业务任务结果尚未提交 | `primary-trace.jsonl` 第 4 条：`ledger_state=applied`、`AIP_product_submitted=false` | 同屏显示“资源修改已完成”和“协调者未收到回复” |
| 主执行智能体调用修改工具并收到返回 | 同文件第 2、3 条：`mcp_modify_invocation`、`mcp_modify_returned`，工具为 `db.restore_writes` | 在“修改完成”节点后画断点 |
| 协调者由超时触发接管 | `takeover-timeline.json` → `timeline[event=coordinator_timeout_triggered_takeover]`：`reason=TimeoutError`，UTC 09:42:04.448493 | “超时 → 查找备用 → 交接任务” |
| 交接包携带同一操作、未确认状态及剩余任务 | `handover-message-excerpts.json` → `[0].payload.args.resume_package`：`operations[0].status=delivery_unknown`、`remaining_tasks[0].tool=db.restore_writes`；`[0].payload.kind=resume` | 交接包只写“任务、证据、操作记录”，无需显示长 ID |
| 备用返回“已执行，跳过”及已保存的只读解除结果 | 同文件 → `[1].payload.operation.state=skipped_already_applied`；`[1].payload.facts` 中 `read_only=false`；对应 `result.json` → `products[2].product` | “查账发现已完成 → 复用结果 → 跳过重复修改” |
| 跳过后重建应用连接并验证订单 | `result.json` → `products[3].payload.tool=application.status`、`products[4].payload.tool=application.pool_rebuild`、`products[5].payload.tool=incident.verification`；连接池版本 22→23 | 接管链路继续接到“重建连接池 → 订单验证” |
| 该数据库修改只记录到 1 次 MCP 调用 | `result.json` → `worker_exit_and_mcp.counts.operations[0].invocations=1`、`returned=1` | 结果卡：“恢复写入工具调用 1 次” |

备用返回的 `read_only=false` 沿用17:41:44.552390的观察结果，接管回复时间为17:42:05。画面写“读取操作记录，复用结果”。

可直接使用的口语化说明：

> 数据库智能体修改完成后，在回复之前退出。备用接管任务，读取主备共用的操作记录，跳过已完成修改，再重建连接池并验证订单。

接管时间的可用事件：主进程退出为 UTC 09:41:44.663452691；协调者触发接管为 09:42:04.448493；交接包发送为 09:42:05.111754；备用“已执行，跳过”回执为 09:42:05.144490。统一加 8 小时后可作为北京时间叠字。定位来源均在 `takeover-timeline.json` 对应事件中；顺序图通常只需显示阶段。

## 6. 可直接交给制图者的三张机制图

**图 A：故障与证据。** 中心“订单异常”，分成三栏：“运维：入口 v1”“应用：当前连接只读”“数据库：确认只读”。容器运行、无阻塞会话作为辅助检查结果。
